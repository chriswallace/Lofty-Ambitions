# Lofty Ambitions security architecture — pre-Steam snapshot

Lofty Ambitions is an unreleased offline tower-management game. The local player owns the simulation and intentionally can edit arbitrary chosen save destinations. Simulation cash/progression are fictional and not security assets. Relevant lower-trust inputs are exchanged save files, native resource bytes when a less-trusted actor can modify them, launcher arguments/environment, downloaded build inputs, and pull-request code running on CI. Protected resources are the player's existing tower/recovery files, native process integrity, developer environment, and eventual release artifacts.

SwiftPM builds shared TowerCore (simulation/validation/persistence), TowerSession (commands/recovery/replay), TowerArt (bundled atlas/PNG), and TowerPresentation (scene). AppKit TowerApp is the native Mac frontend; TowerDesktop + plain-C CDesktop/SDL/stb is Windows and optional Mac. TowerReplay is a CLI. Windows packaging and clean-machine execution remain unverified. No runtime network client/server, HTTP auth, browser/webview, exported helper/IPC, cloud service, secrets, real-money service, or Steam runtime exists in this snapshot. In-process gameplay controls are not a remote authorization boundary.

Save flow: NSOpenPanel or SDL callback -> TowerSaveStore.read -> whole Data/JSON decode -> TowerState.validated -> active state, rendering, simulation, autosaves and recovery. Version/count/geometry/value/subsystem checks exist; examine arithmetic before validation, unbounded nested arrays/strings, and accepted state consumed later. Opening reads before preserving current state. Recovery uses timestamp/UUID filenames and atomic writes. Imported/recovery files require Save As. Unreadable autosaves are copied before replacement, and failure blocks autosave.

CDesktop loads publisher-bundled PNGs via stb and local OS fonts (or launcher-provided overrides) via stb_truetype, caches textures/text within budgets, and queues asynchronous native dialog results with mutex/refcount/alive lifetime. Establish a real lower-trust resource delivery path before elevating parser defects. No custom untrusted native bridge is exported.

Developer scripts select installed Swift/SDL/VS tools and build package-controlled source. SDL archives and downloaded notices have pinned hashes; workflow actions are commit-pinned. CI uses pull_request/push, contents:read, no visible secrets or pull_request_target, and uploads logs/packages. Installed toolchain identity, OS filesystem ACLs, published signatures, future GitHub settings, and Windows loader behavior are not established by source. The Mac distribution is explicitly ad-hoc signed development output. No configured Git repository/remote exists.

Offline tests and parity fixtures are useful references, but their previous passing logs are not audit execution evidence. Current audit is SOURCE-ONLY: a complete launcher proving no external networking, empty allowlisted environment, read-only source/tools, scratch-only writes, and low CPU/memory/process/file/disk/wall-clock limits together is not established. No target build/test/fuzzer or malformed fixture may be executed in this audit. Return exact source-grounded execution blockers as needs_validation; ordinary hardening without a violated boundary is not a vulnerability. Agent outputs use source checks (artifact:null); no retained executable artifacts are promoted.

No prior compatible audit ledger or findings exists. Reviewed revision is the immutable source-manifest.json digest in run-metadata.json, not a fabricated commit. Initial scope: Sources, Tests, scripts, .github, vendored stb, runtime artwork, Package.swift. Marketing, generated builds/media, live Steam/Cloudflare/GitHub services, and actual installed PC/release artifacts are excluded. Mac and SDL implementations provide sibling comparisons; no meaningful external product baseline was established.

Selected companions: native memory/FFI for SDL/stb lifetime/bounds; desktop/local files for user-authorized file actions and pending dialogs; data lifecycle for save/recovery; supply-chain/release for pinned downloads, CI and packaging; resource limits for lower-trust file decoding. Browser/web protocol, AI, cloud deployment, kernel/privileged IPC and multiplayer classes have no visible runtime surface in this snapshot. Steam implementation will be reviewed separately after this audit completes.
